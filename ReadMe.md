# Принципы SOLID

## Single Responsibility Principle
- **Реализация**: Каждый класс имеет только одну причину для изменения и отвечает за одну функциональность
- **Классы**: 
  - `OperationFactory` - занимается только созданием операций
  - `BankAccountFactory` - отвечает только за создание банковских счетов
  - `CategoryFactory` - отвечает только за создание категорий
  - Классы в директории `Commands` - каждая команда реализует только одну конкретную операцию

## Open/Closed Principle
- **Реализация**: Классы открыты для расширения, но закрыты для модификации
- **Классы**:
  - `Command` (абстрактный класс) и его расширения в директории `Commands`
  - `CommandDecorator` - позволяет добавлять новое поведение без изменения существующих классов
  - Система декораторов `CommandTimeDecorator` и `CommandBlankDecorator`

## Liskov Substitution Principle
- **Реализация**: Подклассы могут использоваться вместо их родительских классов без нарушения работы программы
- **Классы**:
  - Иерархия `Command` и его реализации
  - Реализации `IDataBase` (`CashDateBase`, `SQLDateBase`, `RunTimeDataBase`) взаимозаменяемы

## Interface Segregation Principle
- **Реализация**: Интерфейсы разделены на специализированные интерфейсы вместо одного крупного
- **Классы**:
  - `IExporter` - для экспорта данных
  - `IImporter` - для импорта данных
  - `IDataBase` - для работы с базой данных

## Dependency Inversion Principle
- **Реализация**: Высокоуровневые модули не зависят от низкоуровневых, оба зависят от абстракций
- **Классы**:
  - Использование DI-контейнера в `Program.cs` для внедрения зависимостей
  - Команды зависят от абстрактного интерфейса `IDataBase`, а не от конкретной реализации
  - Использование фабрик для создания объектов

# Принципы GRASP

## Low Coupling (Низкая связанность)
- **Реализация**: Компоненты системы слабо зависят друг от друга
- **Классы**:
  - Использование интерфейсов (`IDataBase`, `IExporter`, `IImporter`)
  - Внедрение зависимостей через DI-контейнер в `Program.cs`

## High Cohesion (Высокая связность)
- **Реализация**: Классы ответственны за тесно связанный функционал
- **Классы**:
  - Команды в директории `Commands` - каждая отвечает за конкретную операцию
  - `Operation`, `BankAccount`, `Category` - модели данных с четкой ответственностью

## Controller (Контроллер)
- **Реализация**: Управление запросами пользователя делегируется специальным контроллерам
- **Классы**:
  - Классы команд в директории `Commands` - обрабатывают конкретные действия пользователя
  - `MainMenu` - координирует верхнеуровневые действия пользователя

# Паттерны GoF

## Command
- **Классы**:
  - Абстрактный класс `Command` и все его реализации в директории `Commands`
- **Обоснование важности**: Позволяет отделить исполнителя операции от отправителя, поддерживает отмену действий, логирование и другие возможности

## Decorator
- **Классы**:
  - `CommandDecorator`, `CommandTimeDecorator`, `CommandBlankDecorator`
  - Фабрики декораторов `CommandDecoratorFactory`, `CommandTimeDecoratorFactory`, `CommandBlankDecoratorFactory`
- **Обоснование важности**: Позволяет гибко расширять поведение объектов без изменения их кода, добавляя новый функционал (замер времени выполнения)

## Factory Method
- **Классы**:
  - `OperationFactory`, `BankAccountFactory`, `CategoryFactory`, `CommandDecoratorFactory`, `CommandBlankDecoratorFactory`, `CommandTimeDecoratorFactory`
- **Обоснование важности**: Инкапсулирует знание о том, какие конкретные классы создавать, обеспечивает гибкость при создании объектов

## Proxy
- **Классы**:
  - `CashDateBase` является заместителем `SQLiteDateBase`, чтобы не нужно было лишний раз идти в БД, если нужно просто вернуть объект
- **Обоснование важности**: Ускоряет работу приложения, за счет отсеивания лишних запросов к БД

## Template Method
- **Классы**:
  - `IExporter`, `CSVExporter`, `JSONExporter`
- **Обоснование важности**: основная логика работы с экспортом определяется в шаблонном методе в `IExporter`, а `CSVExporter` и `JSONExporter` только опаределяют как будет производиться парсинг данных


# Dependency Injection (Внедрение зависимостей)
- **Классы/модули**:
  - Конфигурация DI-контейнера в методе `ConfigureServices` в `Program.cs`
- **Обоснование важности**: Уменьшает связанность между компонентами, упрощает тестирование и замену реализаций
